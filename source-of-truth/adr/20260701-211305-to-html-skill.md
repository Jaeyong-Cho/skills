# ADR: To-HTML Skill

**Date:** 2026-07-01

## Context

Reading directing/planning/evaluate output as plain markdown is functional but cognitively heavy. A `/to-html` skill renders any file the user points at into a rich, readable HTML document — Kanagawa theme, visual components chosen per content type, Mermaid.js diagrams for explicit relationships. Viewing tool only; no pipeline integration.

## Decision

A model-invoked skill at `to-html/skill.md`. The agent reads the source file, generates a complete and faithful HTML render, and writes it beside the source with a `.html` extension.

**Two hard constraints drive every design choice:**
1. No information loss — every section and item from the source must appear in the HTML
2. No hallucinated structure — no headings, groupings, or relationships added that aren't in the source

## Design

**CSS template:** `../references/kanagawa.css` — full palette as CSS custom properties, base styles, card variants (`.card.goal`, `.card.failure`, `.card.ambiguous`, `.card.good`, `.card.action`), checklist styles, table styles, mermaid container. The skill reads this file and embeds it inline in the generated `<style>` tag so the HTML is fully self-contained.

**Semantic color roles (from kanagawa.css):**
| Section type | CSS class | Accent color |
|---|---|---|
| Goal, info | `.card.goal` | `--crystal-blue` #7E9CD8 |
| Failure, error, bad | `.card.failure` | `--autumn-red` #C34043 |
| Ambiguous, warning | `.card.ambiguous` | `--carp-yellow` #E6C384 |
| Good, direction, success | `.card.good` | `--spring-green` #98BB6C |
| Action, steps, sequence | `.card.action` | `--wave-aqua-2` #7AA89F |
| Special, context, design | `.card.special` | `--oni-violet` #957FB8 |

**Visual components, chosen by content — not applied uniformly:**
- Action sequence steps / evaluation criteria / checklists → `.checklist` with `<input type="checkbox">`
- Named sections → wrapped in `.card` with matching variant class
- Explicit relationships in the source (arrows `→`, `->`; words "leads to", "depends on", "feeds into") → Mermaid.js diagram, type chosen per content (flowchart for pipelines, sequence for interactions, etc.)

**Mermaid.js theming** — every mermaid block opens with:
```
%%{init: {'theme': 'base', 'themeVariables': {'primaryColor': '#2A2A37', 'primaryTextColor': '#DCD7BA', 'primaryBorderColor': '#7E9CD8', 'lineColor': '#727169', 'secondaryColor': '#1F1F28', 'tertiaryColor': '#2A2A37', 'edgeLabelBackground': '#1F1F28', 'clusterBkg': '#2A2A37', 'titleColor': '#DCD7BA', 'nodeTextColor': '#DCD7BA', 'edgeStrokeColor': '#727169'}}}%%
```

**Output location:** same directory as source, same filename, `.html` extension. Source `.md` is never modified.

## Action Sequence

1. Create `to-html/` directory in the skills root.
2. Write `to-html/skill.md` — model-invoked, description triggers on "to html", "render this", "convert to html", "show this visually", "visualize this". Steps: read source file → read `../references/kanagawa.css` → generate HTML (inline CSS, mermaid CDN, content) → write output.
3. Add the card/section mapping table and visual component rules to the skill body (which class to use per section name).
4. Add the Mermaid CDN `<script>` tag and default themeVariables init block to the skill's HTML boilerplate section.
5. Add faithfulness rules to the skill: every section from source must appear; no diagram unless source has explicit relationship language; no structure added that isn't in the source.

## Test-Loop Design

No automated test-loop — skill output is HTML rendered by AI; correctness is qualitative and requires human visual inspection. Evaluation is manual.

## Evaluation Criteria

Run `/to-html` on the existing ADR (`source-of-truth/adr/20260701-003237-verification-layer-skill-upgrades.md`) and open the output in a browser.

**Good (all must pass):**
- HTML file exists at same path as the ADR with `.html` extension
- Background is dark (`#1f1f28`), text is light (`#dcd7ba`) — Kanagawa visible
- All sections from the ADR appear: Context, Decision, Design, Action Sequence, Test-Loop Design, Evaluation Criteria
- Action Sequence items render as checkboxes
- No section or item from the ADR is missing in the HTML
- No section or heading appears in the HTML that isn't in the ADR
- Mermaid diagrams (if any) render without console errors; no diagram drawn for content without explicit relationship language

**Ambiguous (acceptable):**
- Visual grouping wraps related ADR fields into a card — acceptable if it maps 1:1 to source sections
- Minor reordering within a section (e.g. checkbox before prose) — acceptable if no content lost

**Bad (any one fails the evaluation):**
- Any ADR section missing from the HTML
- Any heading or content block in HTML not present in the ADR
- Mermaid diagram shows relationships not stated in the ADR
- Kanagawa colors not applied (page renders with browser defaults)
