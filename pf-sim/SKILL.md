# VAO Scenario Simulation

Trace a scenario through real source code. Grill at each decision point. Surface the reason behind the result or confirm/deny the hypothesis.

---

## Step 1: Capture scenario + hypothesis

Read the user's scenario. Extract:

- **Scenario** — what happens: input, trigger, action
- **Hypothesis** — what the user thinks will happen, or what result they want to understand
- **Unknown** — what they want confirmed or explained

If hypothesis is missing, ask once: *"What do you expect to happen, or what are you trying to understand?"*

---

## Step 2: Find entry point

From the scenario, locate the entry point in source code:

```bash
grep -rn "<trigger or function name>" src/ 2>/dev/null
```

Read the entry point file in full. Map the first hop:

```
Scenario input → entry point (file:line)
```

---

## Step 3: Simulate — step by step

Trace execution from entry point forward. At each hop:

1. **Announce hop** — `"Now at: file:line — <what this code does>"`
2. **Read exact lines** — quote relevant snippet
3. **Grill** — one question at a time via `AskUserQuestion` (discrete options) or plain text (open-ended):
   - *What does this do with the scenario input?*
   - *Which branch does this take? Why?*
   - *What state changes here?*
   - *Does this match your hypothesis?*
   - *What would cause this to behave differently?*

Track internally:
- Each hop and what it does with the scenario input
- Branch taken and why
- State at each point
- Where behavior matches or diverges from hypothesis
- Surprises or non-obvious findings

User can say **"wrap up"** to compress remaining hops and jump to conclusions.

---

## Step 4: Conclude

Summarize findings:

```
Hypothesis: <what user expected>
Result:     <what code actually does>
Verdict:    ✅ Confirmed / ❌ Denied / ⚠️ Partial

Reason:
- <key finding 1 — file:line>
- <key finding 2 — file:line>

Open questions:
- <anything unresolved>
```

Ask via `AskUserQuestion`: "Ready to generate the HTML report?"

---

## Step 5: HTML report

Follow `../pfj-grill/REPORT.md` for structure, styling, interactivity, and generation rules.

Derive slug from scenario (lowercase, hyphens, max 40 chars).

Save: `.pf/reports/sim/YYYY/MM-DD-<slug>.html`

```bash
mkdir -p .pf/reports/sim/YYYY
```

Header: scenario title · date · verdict (✅/❌/⚠️).
Footer: `Generated by pf-sim · date · slug`

**Always include:**
- **Execution trace** — vertical timeline: each hop as `file:line → what it does → state`. Highlight the decisive hop where behavior diverges from or confirms hypothesis.
- **Verdict** — callout box: hypothesis vs actual result, one-line reason
- **Key findings** — bullet list with `file:line` citations

**Include when content warrants:**
- **Branch map** — decision points as a tree: which branch taken, which skipped, why
- **State diagram** — how state mutates across hops
- **Before/after** — if scenario reveals a difference from expected behavior
- **Open questions** — unresolved unknowns worth investigating next

Print path:
```
Report: .pf/reports/sim/YYYY/MM-DD-<slug>.html
```
