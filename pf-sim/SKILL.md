# VAO Scenario Simulation

Trace a scenario through real source code. Grill at each decision point. Surface the reason behind the result or confirm/deny the hypothesis.

## Step 1: Capture scenario + hypothesis

Read the user's scenario. Extract:
- **Scenario** — input, trigger, action
- **Hypothesis** — what user thinks will happen, or what they want to understand
- **Unknown** — what they want confirmed or explained

If hypothesis missing, ask once: *"What do you expect to happen, or what are you trying to understand?"*

## Step 2: Find entry point

Locate entry point: `grep -rn "<trigger or function name>" src/ 2>/dev/null`

Read entry point file in full. Map first hop: `Scenario input → entry point (file:line)`

## Step 3: Simulate — step by step

Trace execution from entry point forward. For each hop — stop, ask, wait for answer, then proceed:

1. **Announce** — `"Now at: file:line — <what this code does>"`
2. **Quote** — show the exact relevant lines with `file:line` header inline
3. **Ask** — one question via `AskUserQuestion` (discrete) or plain text (open): what do you expect here, which branch will be taken, what state changes, does this match your hypothesis?
4. **Confirm** — after user answers, state whether they were right and why, then move to next hop

Do not advance to the next hop until the user has responded. Track: branch taken + why, state changes, matches/diverges from hypothesis, surprises.

User can say **"wrap up"** to compress remaining hops and jump to conclusions.

## Step 4: Deep-dive questions

After all hops are traced, ask follow-up questions about the simulation — no limit. One at a time via `AskUserQuestion` or plain text. Examples: why did this branch win, what would happen if this input changed, is this the right layer for this logic, what edge cases does this miss, what surprised you?

Keep going until the user says **"done"** or **"wrap up"**.

## Step 5: Conclude

```
Hypothesis: <what user expected>
Result:     <what code actually does>
Verdict:    Confirmed / Denied / Partial

Reason:
- <key finding 1 — file:line>
- <key finding 2 — file:line>

Open questions:
- <anything unresolved>
```

Ask via `AskUserQuestion`: "Generate the HTML report?" — if no, skip Step 6 and stop.

## Step 6: HTML report

Follow `../pfj-grill/REPORT.md` for structure, styling, interactivity, and generation rules.

Derive slug from scenario (lowercase, hyphens, max 40 chars).

Save: `.pf/reports/sim/YYYY/MM-DD-<slug>.html`
Header: scenario title · date · verdict (confirmed/denied/partial).
Footer: `Generated by pf-sim · date · slug`

Always include: execution trace timeline (file:line → action → state, highlight decisive hop), verdict callout (hypothesis vs actual, one-line reason), key findings with file:line.
Include when warrants: branch map (decision tree), state diagram, before/after, open questions.

```
Report: .pf/reports/sim/YYYY/MM-DD-<slug>.html
```
