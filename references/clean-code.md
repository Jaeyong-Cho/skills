# Clean Code

1. Clean Code: Write code that is readable, understandable, and easy to change.
2. Meaningful Names: Choose names that clearly reveal intent.
3. Functions: Keep functions small, focused, and at one level of abstraction. (Not conflit with `deep-modules.md`. The interface of others should narrow, not the private functions)
4. Comments: Make the code explain itself; use comments only when necessary.
5. Formatting: Use consistent formatting to make the structure and relationships of code obvious.
6. Objects and Data Structures: Separate behavior from data and hide implementation details behind abstractions.
7. Error Handling: Handle errors clearly and keep error handling separate from normal logic.
8. Boundaries: Isolate external systems and libraries so their changes have limited impact.
9. Unit Tests: Write fast, independent, repeatable, and clear tests.
10. Classes: Keep classes small, cohesive, and responsible for one kind of change.
11. Systems: Separate system construction from system use and isolate complexity.
12. Emergence: Let good design emerge through simple principles and continuous refinement.
13. Concurrency: Isolate concurrency concerns and minimize shared state.
14. Successive Refinement: Start with working code and improve it through successive refinement.
15. Refactoring SerialDate: Refactor systematically by identifying code smells and improving the design incrementally.
16. Smells and Heuristics: Use code smells and heuristics to continuously identify and improve design problems.
