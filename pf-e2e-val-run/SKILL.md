# VAO Validation — Run + Report

## Step 1: Resolve slug + scope

If user provides slug, use it. Otherwise list and ask: `ls validate/`

Verify scaffold: `ls validate/<slug>/cases/ 2>/dev/null` — missing → tell user to run `pf-e2e-val` first.

**Determine scope:**
- User names specific case(s) → run only those
- User says "all" or "run all" → run all cases
- Otherwise → `ls validate/<slug>/cases/` and ask which to run

## Step 2: Run

For each selected case (or all if "run all"):

```bash
cd validate/<slug>/cases/<N>-<name>
python run.py
```

Print stdout per case. Note pass or fail. Each `run.py` writes its own `result.json`.
Show final pass/fail count after all complete.

## Step 3: Rich HTML report

Follow `../pfj-grill/REPORT.md` for structure, styling, interactivity, and generation rules.

Read `result.json` for each case that was run.

Save: `.pf/reports/validate/YYYY/MM-DD-<slug>.html`
Header: `e2e-val-run: <slug>` · date · scope (specific/all) · one-line outcome.
Footer: `Generated by pf-e2e-val-run · date · slug`

Always include: pass-rate progress bar (by type), results table (name, type, pass/fail, last log), failure diffs + log trace.
Include when warrants: pattern analysis by layer, log patterns, coverage map (most useful when all cases run).

```
Report: .pf/reports/validate/YYYY/MM-DD-<slug>.html
```

If failures or patterns revealed unexpected behavior → suggest running `/pf-research` to record it.
