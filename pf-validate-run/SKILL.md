# VAO Validation — Run + Report

## Step 1: Resolve slug

If user provides feature name or slug, use it. Otherwise:

```bash
ls validate/
```

List available slugs and ask which to run.

Verify scaffold exists:

```bash
ls validate/<slug>/run_all.py 2>/dev/null
```

Missing → tell user to run `/pf-validate` first to scaffold.

---

## Step 2: Run

```bash
cd <project-root>
python validate/<slug>/run_all.py
```

Print stdout as it runs. `run_all.py` writes per-case `result.json` and `validate/<slug>/report.html` (lightweight stats).

Show final pass/fail count and path to lightweight report.

---

## Step 3: Rich HTML report

Follow `../pfj-grill/REPORT.md` for structure, styling, interactivity, and generation rules.

Read all `validate/<slug>/cases/*/result.json` files.

Save: `.pf/reports/validate/YYYY/MM-DD-<slug>.html`

```bash
mkdir -p .pf/reports/validate/YYYY
```

Header: `validate: <slug>` · date · one-line outcome.
Footer: `Generated by pf-validate-run · date · slug`

**Always include:**
- **Pass rate** — progress bar: passed / total, broken down by type (happy/edge/error)
- **Results table** — case name, type, status (✅/❌/⚠️), last log line
- **Failure analysis** — for each failed case: actual vs expected diff, log trace, likely cause

**Include when content warrants:**
- **Pattern analysis** — which layer (value/aspect/object) has most failures → where bug lives
- **Log patterns** — recurring messages across cases; signal vs noise
- **Coverage map** — scenarios covered vs missing; gaps to add next

Print path:
```
Report: .pf/reports/validate/YYYY/MM-DD-<slug>.html
```
