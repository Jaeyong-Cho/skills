Check journal: `[ -n "$PFJ_PATH" ] && cat "$PFJ_PATH/today.md" 2>/dev/null`

# VAO Validation — Report

Find validation results for a topic. Run missing cases if needed. Generate HTML report.

## Step 1: Resolve slug

If user provides feature name or slug, use it. Otherwise list and ask: `ls validate/`

Verify scaffold exists: `ls validate/<slug>/cases/ 2>/dev/null` — missing → tell user to run `pf-e2e-val` first.

## Step 2: Check existing results

For each case, check if `result.json` exists:

```bash
ls validate/<slug>/cases/*/result.json 2>/dev/null
```

Show status:
```
Cases found:   N
With results:  N  (result.json exists)
Missing:       N  (never run)
```

If all results exist → skip to Step 4.

## Step 3: Run missing cases

For each case without `result.json`:

```bash
cd validate/<slug>/cases/<N>-<name>
python run.py
```

Print stdout per case. Note pass or fail. Each `run.py` writes its own `result.json`.
Show updated pass/fail count.

Ask via `AskUserQuestion`: "Generate the HTML report?" — if no, skip and stop.

## Step 4: Generate HTML report

Follow `../pfj-grill/REPORT.md` for structure, styling, interactivity, and generation rules.

Read `result.json` for all cases.

Save: `.pf/reports/validate/YYYY/MM-DD-<slug>.html`

```bash
mkdir -p .pf/reports/validate/YYYY
```

Header: `e2e-val: <slug>` · date · pass rate · one-line outcome.
Footer: `Generated by pf-e2e-val-report · date · slug`

Always include: pass-rate progress bar (by type), results table (name, type, pass/fail, last log), failure diffs + log trace.
Include when warrants: pattern analysis by layer, log patterns, coverage map.

```
Report: .pf/reports/validate/YYYY/MM-DD-<slug>.html
```
