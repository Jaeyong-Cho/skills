# Daily Report

Read `../references/document-style.md` first — its Introduction/Abstraction/Detailed structure and priority order (key-value > table > bullets > prose) govern every section this skill writes.

## Execution model: this session drafts, haiku renders diagrams in parallel

Drafting the report (steps 1-4, 6-8 below) is reasoning-heavy and stays in this session. Step 5 — one diagram per content item — is mechanical and independent per item once its text is drafted, so it fans out to a haiku-class subagent per item, dispatched together in one batch (never one at a time). This session never draws a diagram itself.

1. **Run the day's other skills first** — invoke `/d-handoff`, then `/advisor` (Skill tool), and record each one's output file path. Completion criterion: both have run and a path is recorded for each.
2. **Gather today's sources** — read today's journal file (`~/wiki/journal/YYYY/MM/YYYY-MM-DD.md`), today's research directories (`~/wiki/research/YYYY/MM/YYYY-MM-DD/NN-{job}/`), and the two files from step 1, all in full. Completion criterion: every source is either read in full or confirmed absent.
3. **Split into content items** — one item per topic, task, or research job from the journal/research, plus one "Handoff" item from the handoff file and one "Advisor" item from the advisor file. Completion criterion: every entry from step 2, including the handoff and advisor files, is assigned to exactly one content item.
4. **Draft each content item** in three phases per `../references/document-style.md`: Introduction (1-3 sentences, why/what), Abstraction (the objects, interactions, and relationships involved), Detailed (one representative concrete example, including any research result or finding). Completion criterion: every content item has all three phases, each obeying that file's size limits.
5. **Render each item's insight diagram** — for every content item, **MUST DISPATCH** a separate haiku-class subagent (batch all of them together, in parallel) given that item's three drafted phases. Each renderer: identify the item's key result or insight and decide whether a diagram shows it better than the text alone; if so, pick whichever form fits (flow, relationship, comparison, hierarchy, or timeline — see `../viewpoints/references/catalog.md`'s structure & flow / relationship / comparison / trend & time categories), render it as SVG with mermaid (`mmdc`) or graphviz — whichever is installed, this is an intentional either/or, not a gap to flag — light-mode only, styled with ink `#2a2920`, accent `#9a4929`, line `#e0ddd8`, save it under `~/wiki/journal/YYYY/MM/YYYY-MM-DD-report/{item-slug}.svg` (`mkdir -p` the directory first), then run `python scripts/validate_svg.py <path>` before reporting the path back. A plain task list with no depictable insight gets no diagram — say so rather than forcing one. If a renderer fails, retry it once as a fresh subagent with the same brief; if the retry also fails, drop that item's diagram and note the failure. Completion criterion: every content item from step 3 has either a validated SVG path, an explicit "no diagram" call, or a recorded failure — none silently skipped.
6. **Build the table of contents** — list content item titles in the order they appear, each linking to its section. Completion criterion: ToC entry count equals the content item count from step 3.
7. **Write the markdown report** — assemble ToC + all content items into `~/wiki/journal/YYYY/MM/YYYY-MM-DD-report.md` (`mkdir -p` the parent directory if needed); embed each item's diagram, where rendered, as a markdown image link to `YYYY-MM-DD-report/{item-slug}.svg` right under its heading. If it would exceed the 500-word file cap in `../references/document-style.md`, split the largest content items into separate linked files instead of shrinking their phases. Completion criterion: the file exists with a ToC, every content item's three phases, and every rendered diagram linked.
8. **Assemble the HTML gallery via script** — build a manifest JSON (schema in `scripts/build_report.py`'s docstring) with one entry per content item (title, svg path if rendered, introduction/abstraction/detailed), then run `python scripts/build_report.py manifest.json ~/wiki/journal/YYYY/MM/YYYY-MM-DD-report/index.html` (this re-validates any SVG before embedding and exits with an error rather than shipping a broken one — a safety net behind the per-renderer check in step 5). Completion criterion: `index.html` exists in that directory, embeds every content item — with its diagram where rendered — with no external asset references, and opens standalone in a browser.
9. **Make the gallery servable** — copy `scripts/serve.sh` into `~/wiki/journal/YYYY/MM/YYYY-MM-DD-report/`. MUST NOT run it yourself; the user runs it manually (binds `0.0.0.0:4801`, pass an argument to override the port). Completion criterion: `serve.sh` exists next to `index.html` in that directory.
10. **Update index.md** — update the index.md in the `~/wiki/**/*/index.md`

Tell the user the markdown path, the report directory (containing `index.html` and `serve.sh`), and the URL to open (http://localhost:4801) once they've run it.
