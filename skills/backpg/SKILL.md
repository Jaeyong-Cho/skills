# backpg

The repo's directory tree is the network: every directory carrying an `AGENTS.md` is a **node**, its content the node's **weight**, a `CLAUDE.md` symlink pointing at that `AGENTS.md` making the node visible to both harnesses. A finished session is the forward pass; its mistakes are the **loss**. This skill is the backward pass — find the loss, attribute it to the node whose weight should change, draft the edit, and stop for your gate before writing anything.

1. **Find the loss** — read back over the current agent session's transcript from the start — whatever conversation is already open in this context, regardless of which agent/harness is running it. This skill only ever looks at the session it's invoked from; it does not go hunting through any other session's transcript on disk. For every place the user corrected you, repeated an instruction you'd already been given, or you caught your own mistake, log it as an item: a one-line description plus the verbatim quote proving it happened. No quote, no item — drop anything you can't quote exactly. Cross-check each against `` `git ls-files --cached --others --exclude-standard -- '*AGENTS.md'` `` (git-tracked or untracked-but-not-ignored only — this naturally skips `.git/`, package/dependency install locations, build output, and anything else this repo already treats as not-source): if an instruction already covered it and got missed or violated anyway, tag it a **violation** (the wording needs sharpening) rather than a **gap** (nothing covered it). Completion criterion: every correction and self-caught mistake in the session is logged as a gap or a violation with its quote, none logged twice.

2. **Attribute each item to a node** — for each gap/violation, find the file(s) it's actually about and walk that path up toward the repo root one directory at a time. Stop at the first directory whose scope matches the mistake: broad enough that the same lesson applies to other files nearby, narrow enough that it doesn't force unrelated work elsewhere in the repo to load it. A mistake about one function's error handling stops at that file's own directory, not the root; a mistake about how every command in the repo should be run stops at the root. An item not tied to any specific file (a repo-wide workflow rule) also targets the root. **Never stop inside a directory git itself doesn't treat as source** — run `git check-ignore -q <dir>` (or it isn't inside the repo's working tree at all, e.g. sits above the repo root); either way it's not a node, so keep walking up to the next real directory above it. This covers VCS internals (`.git/`), package/dependency install locations (`node_modules/`, `vendor/`, `.venv/`, `site-packages/`, ...), and build output (`dist/`, `build/`, ...) without hardcoding the list. If no `AGENTS.md` exists yet at the directory you stopped on, target it anyway — step 4 bootstraps it. Completion criterion: every item from step 1 has exactly one target directory, and `git check-ignore -q` is clean (non-ignored) for every one of them.

3. **Draft one edit per node** — group items by target node. For each node draft the smallest fix: ADD a new instruction (gaps), REWRITE existing wording (violations), or REMOVE text the session proved wrong. Each edit carries its verbatim quote and a one-line rationale. Every node's `AGENTS.md` has a **budget: 5,000 tokens (~20KB), estimated as `wc -c AGENTS.md` / 4** — it loads on every session touching that directory, so a bloated file taxes every one of them. Check the node's current size before adding; at or over budget, an ADD must name the REMOVE/REWRITE elsewhere in the same file that pays for it (zero-sum), and a node whose file already exceeds budget gets a shrink pass instead of a new instruction. If the node has no `AGENTS.md` yet, read `references/bootstrap.md` for the starter content and symlink step to fold in alongside the edit. Completion criterion: every node from step 2 has a drafted diff, each hunk traceable to one item's quote, and no diff leaves its node's file over budget.

4. **Gate on accept/reject** — show each node's diff one at a time: path, before/after, quote, one-line rationale. Ask accept or reject. Write nothing before this step, assume nothing. Completion criterion: every drafted node from step 3 has an explicit accept or reject.

5. **Apply accepted edits** — for each accepted node: if `AGENTS.md` exists, apply the diff directly; if it's new, create it from the bootstrap template with the edit folded in, then symlink `CLAUDE.md -> AGENTS.md` in that directory. If a real (non-symlink) `CLAUDE.md` already sits there, stop and flag the divergence instead of overwriting it. Leave rejected nodes untouched. Completion criterion: `git status` shows changes only in accepted nodes' `AGENTS.md`/`CLAUDE.md`, matching them exactly.

Close with a table: node path, edit type, one-line description — accepted edits only.

Not doing: no cross-session rejection memory, no evidence-count threshold before an item can be proposed, no configurable per-repo budget override (the 5,000-token cap is fixed). Single-session volume is low enough that your accept/reject at the gate is the only check that matters — add a ledger if repeat proposals for the same rejected item become annoying, or a config knob if 5,000 tokens is consistently wrong for this repo.
