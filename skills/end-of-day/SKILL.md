# End of Day

Read `../references/document-style.md` first — its Introduction/Abstraction/Detailed structure and priority order (key-value > table > bullets > prose) govern every section this skill writes.

1. **Run the day's other skills first** — invoke `/d-handoff`, then `/advisor` (Skill tool), and record each one's output file path. Both read today's in-progress work from `~/wiki/today/journal.md` and `~/wiki/today/research/NN-{job}/`. Completion criterion: both have run and a path is recorded for each.
2. **Resolve finished goals** — read `~/wiki/goals.md`; if it lists any goal under `## Active`, ask the user (AskUserQuestion, multi-select) which of those are now resolved. Move each selected slug's line from `## Active` to `## Done` in place. Skip silently if `goals.md` doesn't exist or lists no active goals. Completion criterion: every active goal has been asked about, and resolved ones are moved to `## Done` before step 3 archives them.
3. **Archive today's working files** — run `bash scripts/archive_today.sh` (relative to this skill's directory). It moves `~/wiki/today/journal.md` into `~/wiki/journal/YYYY/MM/YYYY-MM-DD.md` and each `~/wiki/today/research/NN-{job}/` into `~/wiki/research/YYYY/MM/YYYY-MM-DD/`, archives any goal moved to `## Done` in `~/wiki/goals.md` into that same dated research folder, removes `~/wiki/today/`, then re-links every remaining `## Active` goal into a fresh `~/wiki/today/research/NN-{slug}/`. The date used is `today/journal.md`'s creation date, not the date the script happens to run on — a session that starts in the evening and is archived after midnight still files under the day it started. Run this after steps 1-2, not before — d-handoff and advisor still need `today/` in place, and step 2's Done goals need to already be marked. Completion criterion: the script ran and `~/wiki/today/` either no longer exists or holds only re-linked active goals.
4. **Seed tomorrow's work context** — write a fresh `~/wiki/today/journal.md` (`mkdir -p` the parent; step 3 just removed this file, so create it new — don't reuse an old one), with two sections:
   - `## Next Goal` — from the advisor file written in step 1, the single highest-priority candidate: prefer a `task`-typed opportunity candidate; if none, take the first candidate listed. One line, in the advisor's own words, plus the advisor file's path. Skip this section if advisor found no candidates.
   - `## Context to Continue` — from the handoff file written in step 1, its "Open Items" and "Carried Decisions" copied as bullets, exact not paraphrased, plus the handoff file's path for full detail. Skip this section if the handoff has neither.
   If both sections are skipped, skip the whole step and say so. Completion criterion: `~/wiki/today/journal.md` exists with at least one section populated, or an explicit "nothing to carry" note.
5. **Gather today's sources** — read today's journal file (`~/wiki/journal/YYYY/MM/YYYY-MM-DD.md`), today's research directories (`~/wiki/research/YYYY/MM/YYYY-MM-DD/NN-{job}/`), and the two files from step 1, all in full. Completion criterion: every source is either read in full or confirmed absent.
6. **Split into content items** — one item per topic, task, or research job from the journal/research, plus one "Handoff" item from the handoff file and one "Advisor" item from the advisor file. Completion criterion: every entry from step 5, including the handoff and advisor files, is assigned to exactly one content item.
7. **Draft each content item** in three phases per `../references/document-style.md`: Introduction (1-3 sentences, why/what), Abstraction (the objects, interactions, and relationships involved), Detailed (one representative concrete example, including any research result or finding). Completion criterion: every content item has all three phases, each obeying that file's size limits.
8. **Build the table of contents** — list content item titles in the order they appear, each linking to its section. Completion criterion: ToC entry count equals the content item count from step 6.
9. **Write the markdown report** — assemble ToC + all content items into `~/wiki/journal/YYYY/MM/YYYY-MM-DD-report.md` (`mkdir -p` the parent directory if needed). If it would exceed the 500-word file cap in `../references/document-style.md`, split the largest content items into separate linked files instead of shrinking their phases. Completion criterion: the file exists with a ToC and every content item's three phases.

Tell the user the markdown report path.
