# HTML Report Spec for pfj-discuss

Generate a **single self-contained HTML file** — no external CDN, no network requests required. All CSS in `<style>`, all JS in `<script>`. The file must render correctly when opened from disk (`file://`).

---

## Required Sections (in order)

### 1. Header bar
- Topic title (large)
- Date · Duration estimate (count questions × avg 2 min) · Total questions
- Short one-sentence summary of what was decided

### 2. Stats row — 4 cards
| Card | Value |
|------|-------|
| Questions asked | count |
| Branches explored | count of distinct decision paths |
| Action items | count |
| Decisions made | count of explicit conclusions |

### 3. Executive Summary
2–4 bullet points. What was decided and why, at the level of a manager briefing.

### 4. Decision Tree
Render as a collapsible CSS tree. Each node = one question. Color the path taken green, skipped branches gray, open/unresolved branches amber.

Structure:
```
Root: [topic]
├── Q1: [question] → [answer given]
│   ├── Branch A: [follow-up] → [answer]
│   └── Branch B: skipped
├── Q2: ...
```

Nodes should be clickable to expand/collapse sub-branches.

### 5. Full Q&A Transcript
Numbered list. Each entry:
- **Q[n]**: question text (gray label "Claude")
- **A**: user's answer (indented, slightly different background)
- Optionally: a one-line annotation of the conclusion this answer led to

Use `<details><summary>` for long answers to keep the page scannable.

### 6. Action Items
Checkable list (JS toggles `text-decoration: line-through` + opacity on click). Group by category if more than 5 items. Show priority level if it surfaced in discussion.

### 7. Conclusions
One block per resolved branch. Format:
```
[Topic / Branch]
Decision: ...
Rationale: ...
Open questions (if any): ...
```

### 8. Footer
Generated by pfj-discuss · date · topic slug

---

## Styling Guidelines

**Theme**: dark background preferred (`#0d1117` or similar), high-contrast text. Use a clean sans-serif (system-ui). Code/commands in monospace.

**Color palette** (adapt as fits):
- Primary accent: `#58a6ff`
- Success / taken path: `#3fb950`
- Warning / open branch: `#d29922`
- Muted / skipped: `#6e7681`
- Card background: `#161b22`
- Body background: `#0d1117`

**Layout**: max-width 900px, centered. Stats cards in a 4-column flex row. Sections separated by subtle `<hr>`.

**Charts / Diagrams**: Use inline `<canvas>` with vanilla JS (no libraries) for any statistics charts. Keep them optional — only add if the data warrants it (e.g. >10 questions, multiple branches). Bar charts showing question counts per topic cluster are always welcome.

**Interactivity**:
- Collapsible decision tree nodes
- Checkable action items
- Smooth scroll to section via a sticky nav bar at the top
- "Copy to clipboard" button on the conclusions section

---

## Generation Rules

- **Do not hallucinate** content not in the discussion. Every Q&A entry must come from the actual session.
- If a branch was explicitly skipped, still show it in the decision tree as a grayed-out node with label "skipped".
- If action items have associated commands or code snippets from the discussion, render them in `<pre><code>` inside the action item.
- The HTML must pass a basic sanity check: no unclosed tags, no broken JS that would block rendering.
- Prefer semantic HTML (`<section>`, `<article>`, `<details>`, `<summary>`) over div soup.
